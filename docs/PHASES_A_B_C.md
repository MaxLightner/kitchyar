# فازهای A، B و C — وضعیت اجرا

## A — ممیزی و پایه مستقل

- انجام شد: مخزن کیچیار بررسی شد (خالی/خصوصی)، مرزهای معماری، نسخه اولیه مدل داده، قواعد منع انتقال Builder.
- انجام شد: منبع‌های قابل بازاستفاده بررسی شدند: UI چیدو، کد هندسه آرچیار، کنترلر معنایی پنجره در افزونه بلندر؛ گزینه‌های مستقل تولید ورق Furniture Designer و Panelizer مشخص شدند.
- انجام شد: پروژه Android Gradle مستقل با پوسته UI و کنترل‌های CI اضافه شد.
- **باز/نیازمند تأیید:** ساخت واقعی APK توسط CI، نصب/اجرای گوشی، تست ARCore و انتخاب نهایی موتور تولید ورق. این ابزارها در محیط فعلی در دسترس نبودند.

## B — Welcome و مدیریت پروژه

- انجام شد: صفحه خوشامدگویی، ساخت پروژه، ادامه از صفحه پروژه‌ها، نام/تاریخ/تعداد آبجکت در کارت‌ها.
- انجام شد: تغییر نام، تکثیر با شناسه‌های جدید، حذف با تأیید، خروجی پشتیبان JSON و ذخیره محلی نسخه‌دار.
- انجام شد: ابزار آنفولد در کارت پروژه دیده می‌شود ولی تا فاز L غیرفعال است.
- انجام شد: ورود دوباره فایل پشتیبان JSON با شناسه مستقل؛ فایل نامعتبر پروژه موجود را بازنویسی نمی‌کند.
- **باز:** بازیابی نسخه تاریخی/آرشیو پیشرفته.

## C — UI و فضای کار

- انجام شد: نوار پایین با شش دسته، پنل شناور، کنترل Undo/Redo، پنل مشخصات آبجکت، مینی‌مپ با بزرگ‌نمایی و حالت 2D/3D مشترک.
- انجام شد: نمونه حجم مستقل برای تست تعامل، انتخاب/درگ/ورود ابعاد دقیق/کپی/حذف، ذخیره همان مدل مشترک.
- **تفاوت مهم:** 3D این مرحله یک نمای ایزومتریک Canvas برای اعتبارسنجی UI است، نه رندر سه‌بعدی نهایی. AR هنوز غیرفعال و برچسب فاز D دارد.
- **باز:** کارایی/تست لمس روی تبلت واقعی، انتخاب پیچیده پشت آبجکت‌ها، نقشه قابل بزرگ‌کردن، سیستم مواد و هندسه کابینت.

## مرز فاز D

در فاز بعد ابتدا تشخیص کف و کالیبراسیون چیدو با ARCore بومی (و حفظ مقیاس پروژه) پیاده می‌شود. دیوار و بازشوها متعلق به فاز E هستند؛ کابینت واقعی از F آغاز می‌شود. از حجم آزمایشی فاز C برای ساخت BOM استفاده نشود.
